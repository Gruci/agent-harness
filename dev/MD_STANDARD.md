# dev/MD_STANDARD.md — MD 작성 규칙

> 담는 것: 정본 MD를 쓰고 고치는 규칙. 담지 않는 것: 코드 관례(→ `dev/CONVENTIONS.md`)·개별 MD의 내용. 읽는 시점: **MD를 새로 만들거나 수정하기 전**.

MD는 이 프로젝트의 작동 규칙이자 하네스다. 코드에 적용하는 유지보수성 기준을 MD에도 그대로 적용한다.

## 3원칙

| # | 원칙 | 한 줄 정의 |
|---|------|-----------|
| ① | 가독성 | 한 줄·문단·섹션 = **한 의미 단위**. 사람이 훑어서 판단할 수 있어야 한다 |
| ② | 연결성 | 한 사실은 한 곳에만, 다른 곳엔 링크. 모든 MD는 허브에서 도달 가능해야 한다 |
| ③ | 잡동사니 배제 | **grep으로 알 수 있는 것은 적지 않는다** |

## 판정 테스트

> **"이 MD의 한 가지를 고치려면 무엇을 다시 써야 하나?"**

`한 줄만` = 양호 / `한 절 재작성` = 정리 필요 / `파일 통째 재작성` = 한 파일에 책임이 몰린 상태(코드로 치면 모든 일을 떠안은 갓 함수). 코드였으면 리뷰에서 반려될 물건은 MD에서도 반려다.

## 코드 규칙 ↔ MD 등가

| 코드 규칙 (게이트로 강제 중) | MD 등가 |
|---|---|
| 파일 400줄 상한 | 크기 상한 — 단 **기계 분할 금지**, 주제 단위로 나눈다 |
| 파일 단일 책임 | 단일 주제 + 머리 역할 계약 1줄 |
| I/O와 로직 함수 분리 | 라우팅·계약·함정·결정 근거를 절로 분리 |
| 중첩 def 금지 | 괄호·문장 중첩 금지 |
| 재구현 금지 | 한 사실은 한 MD에만, 나머지는 링크 |
| dead code 방치 금지 | 낡은 MD와 허브에서 닿지 않는 고아 MD 제거 |
| 역방향 import 금지 | MD 역할 경계 준수 |

## ③ 성분 판정 — 무엇을 담고 무엇을 안 담나

| 코드 | 성분 | 정본 | MD에 |
|---|---|---|---|
| A | 파일 목록·디렉토리 트리 | `ls`/Glob | ❌ |
| B | 시그니처·props·타입·엔드포인트 목록 | 코드 | ❌ |
| C | 소비처·import·호출 그래프 | Grep | ❌ |
| D | 변경 이력·삭제 기록·날짜 태그 | git log | ❌ (`dev/LESSONS.md`만 예외 — 날짜가 목적) |
| E | 라우팅·계약·함정·결정 근거 | MD 뿐 | ✅ |
| F | 도메인 지식 — 스키마 의미·업무 규칙·외부 API 특성 | MD 뿐 | ✅ |

경계 판정 시험 — **"이 줄을 지우면 다음 세션이 잘못 행동하는가?"**

- 파일명 나열이어도 **절차 계약**이면 E. 예: 새 테이블은 DDL 추가 → schema import → init 호출 순서.
- 시그니처여도 **재사용 지시**면 E. 공용 헬퍼 레지스트리는 "재구현 금지"가 본체다.
- 날짜와 근거가 붙어 있으면 날짜만 D. 이유는 남기고 날짜는 뗀다. 사고 경위는 `dev/LESSONS.md`로.
- 수치 임계값은 코드가 정본. MD엔 "왜 그 값인지"만 남긴다.

## ① 가독성 규칙

| 규칙 | 기준 |
|------|------|
| 한 줄 = 한 사실 | 가운뎃점이나 괄호로 독립 사실을 이어붙이지 않는다. 나열이 필요하면 표나 불릿 |
| 문단 = 한 주제 | "언제 이 절을 읽나"가 한 문장으로 안 되면 절을 쪼갠다 |
| 표 우선 | 병렬 사실 3개 이상은 산문 대신 표 |
| 괄호 중첩 ≤ 2 | 3중 괄호부터는 문장을 다시 쓴다 |
| 코드펜스 트리 금지 | 디렉토리 트리·파일 카탈로그 덤프 금지 — 정본은 Glob |
| 글자 수는 규칙이 아니다 | 의미가 하나면 길어도 된다. 길이는 문제가 있는 곳을 찾는 신호로만 쓴다 |

## ①-1 어휘 — 번역투 한자어 금지

구어체를 걷어내라는 지적을 받으면 반대편으로 넘어가 행정·군대식 한자어를 깔기 쉽다. 두 극단이 모두 반려다. 기준은 **한국 시니어 개발자가 위키에 쓸 법한 말**이다.

| 쓰지 않는다 | 쓴다 | 왜 |
|---|---|---|
| 발화 | 실행 · 트리거 | `trigger` 직역이다. 훅이 "발화"하지 않는다 |
| 잔존 | 남아 있음 · 그대로 유지 | 행정 문서 어휘다 |
| 불요 | 필요 없음 · 조치 없음 | 〃 |
| 수취 | 받기 · 내려받기 | 〃 |
| 표출 | 표시 · 나타남 | 〃 |
| 선점유 | 모킹 · 가짜 값으로 대체 | 무엇을 했는지가 안 보인다 |
| 단일하다 | 하나뿐이다 · 한 곳이다 | `is single` 직역이다 |
| 미표시 · 부재 · 불충족 | 안 나옴 · 없음 · 조건이 아님 | `미/부/불` 접두 남발은 읽는 속도를 떨어뜨린다 |

반대편 금지선도 같이 둔다. "사람이 눈치챌 필요 없다"·"당신이 읽을 곳" 같은 가벼운 말투와 번역기 투 역시 반려다.

문체는 파일 안에서 하나로 통일한다. 내부 MD 는 `~다`, 배포를 전제한 문서는 `~합니다` 를 쓴다.

## ② 연결성 규칙

| 규칙 | 기준 |
|------|------|
| 머리 역할 계약 | 파일 첫 인용구: `> 담는 것: X. 담지 않는 것: Y(→ 링크). 읽는 시점: Z` |
| 계약 격식 표기 | 배포를 전제한 문서는 `> 문서 범위: X. 제외 범위: Y. 열람 시점: Z`를 쓴다 — **슬롯 3개가 같아야 계약이다.** 어휘만 바꾸고 슬롯을 빼면 MD 작성 규칙 검사(검사 25)가 잡는다 |
| 한 사실 한 곳 | 중복 서술 금지 — 정본 아닌 쪽은 링크 1줄 |
| 진입 경로 | 새 MD는 **같은 턴에** 허브 라우팅표에 행 등재 |
| 고아 금지 | 허브에서 도달 불가능한 MD는 존재 이유가 없다 |

## before / after

원본 프로젝트에서 실제로 걷어낸 한 줄이다. 443자에 성분 A·B·C·E가 뒤섞여 있었다.

❌ `utils/ format·company·axes·forecast·briefingApi(fetchBriefingLatest<T>(type?) — /api/briefing/latest 404→null 공용, marketApi 2곳 소비. AumBriefing은 시맨틱 상이로 제외)·treemapLayout(…)`

✅ E/F만 남기고 한 줄에 한 사실로:

- briefingApi: 404→null이 정상 계약이다.
- briefingApi: AumBriefing은 시맨틱이 달라 이 공용을 쓰지 않는다.
- treemapLayout: 값 함수만 공용이다. 계층 구조가 달라 leaf 빌더는 공유하지 않는다.

모듈 목록·시그니처·소비처는 Glob과 Grep이 정본이라 적지 않는다.

## 강제 수단

| 층 | 수단 | 담당 |
|---|---|---|
| 작성 시점 | PostToolUse 훅 → `kernel.runner --file` → 검사 25 | 구조 신호: 코드펜스 트리, 가운뎃점으로 뭉갠 나열, 괄호 중첩, 역할 계약 누락 |
| 기존 파일 유예 | `md_style_baseline.txt` — 여기 등재된 파일은 차단 대신 리포트만 낸다. 목록은 **줄이는 것만 허용** | 래칫(한 번 정리한 수준 아래로 되돌아가지 못하게 잠그는 장치) |
| 사람 판단 | 월 1회 `/md-audit` | 의미 단위 판정, 성분 E/F 선별, 의미 중복 찾기. 기계로 자동화할 수 없는 영역 |

검사 25의 임계값과 판정 로직은 `kernel/gates/md_style.py` 헤더가 정본이다. 오탐이 나면 baseline에 넣지 말고 **문장을 고치는 게 기본**이다.
