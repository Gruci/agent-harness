# dev/TESTING.md — 행동과 경계 테스트

> 담는 것: 책임에 따른 테스트 선택과 회귀 검증 기준. 담지 않는 것: 실행 절차(→ [workflows/test.md](workflows/test.md)). 읽는 시점: 테스트를 작성하거나 변경 계약을 검증할 때.

## 실패를 먼저 확인한다

버그 수정은 재현 테스트를 먼저 실행하여 실패를 확인한다.
새 행동은 인수 조건을 검증하는 테스트를 작성한 뒤 최소 구현으로 통과시킨다.
오탈자나 설정값 하나의 수정에 구현을 그대로 복제하는 테스트를 추가하지 않는다.
단순 리팩터링은 기존 행동 테스트로 변경 전후의 계약을 확인한다.

## 책임에 따른 선택

| 대상 | 검증할 계약 | 실행 방법 |
|---|---|---|
| 정책 | 계산과 상태 전이 및 불변 조건 | 네트워크 없는 단위 테스트 |
| 유스케이스 | 업무 절차와 실패 처리 | 선언된 포트를 대역으로 제공한다 |
| 어댑터 | 실제 저장소나 서비스와의 호환 | 테스트 저장소 또는 외부 경계 픽스처 |
| 전달 | 입력과 출력 및 오류 처리 | 선택한 프레임워크의 실제 요청 경로 |
| 공개 포트 | 호출 서명과 결과 및 실패 계약 | 계약에 맞는 대역을 실행한다 |

정책의 내부 함수를 가짜로 바꾸고 정책이 검증됐다고 보고하지 않는다.
외부 I/O와 시각처럼 테스트가 제어해야 할 경계만 대체한다.
통합 테스트는 내부 호출을 모킹하는 대신 실제 테스트 자원을 사용한다.

## 포트 대역

포트를 선언하지 않은 경계에 대역을 의무화하지 않는다.
선언한 포트는 공개 계약을 구현하는 대역으로 유스케이스를 실행해 검증한다.
이름이 Fake로 시작하는 클래스의 존재만으로 통과시키지 않는다.
기계 검사로 확인한 범위와 실제 행동 테스트가 확인한 범위를 구분한다.
지원하지 않는 언어의 계약 검사는 미검증으로 보고한다.

## 언어와 도구

테스트 명령은 프로젝트에서 선택한 언어와 도구에 맞춰 구성한다.
하네스가 Python으로 실행된다는 이유로 제품 테스트에 pytest를 강제하지 않는다.
소스 위치는 [분류 정본](COMPONENTS.md)에 연결한다.
업무 규칙의 기대값과 실패 조건을 테스트에 적으며 함수 이름 접두어로 책임을 판단하지 않는다.

## 완료 근거

실행 명령과 종료 코드를 기록한다.
테스트가 선택되지 않은 실행은 성공 근거가 아니다.
필수 도구가 없거나 구문 분석을 못 하면 미검증이며 완료가 아니다.
실제 외부 서비스 연결을 대체했다면 검증한 범위를 명시한다.
화면 변경은 소비 API와 연결을 확인하고 렌더링을 검사한다.
