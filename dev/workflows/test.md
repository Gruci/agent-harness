# 테스트 절차

> 담는 것: 테스트 선택과 실행 결과 판정. 담지 않는 것: 테스트 전략(→ [../TESTING.md](../TESTING.md)). 읽는 시점: 테스트를 작성하거나 실행할 때.

## 선택

[테스트 전략](../TESTING.md)을 읽고 현재 프로젝트의 테스트 명령을 확인한다.
변경한 정책과 유스케이스 및 외부 경계를 구분한다.
실패를 검출할 가장 좁은 테스트부터 선택한다.
프로젝트에 없는 언어나 테스트 디렉토리를 습관처럼 가정하지 않는다.

## 작성

버그는 재현 테스트가 실패한 뒤 구현을 고친다.
정책은 외부 서비스 없이 검증한다.
포트에 맞춰 만든 테스트 대역(가짜 구현)이 실제 유스케이스 테스트에서 쓰이는지 확인한다.
내부 정책을 가짜로 바꿔 놓은 테스트로 상위 행동 전체를 검증했다고 판단하지 않는다.
반복 사용할 외부 응답은 픽스처로 보관한다.
테스트를 위해 불필요한 의존성을 추가하지 않는다.

## 실행과 보고

선택한 프로젝트 도구로 대상 테스트를 실행한다.
필요한 통합 검사와 타입 검사 및 빌드를 이어서 실행한다.
명령과 종료 코드를 기록한다.
실패와 미검증 및 실행하지 않은 검사를 구분한다.
선택된 테스트가 없는 실행을 성공으로 보고하지 않는다.
