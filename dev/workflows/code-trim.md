# 변경의 과잉설계 검토

> 담는 것: 현재 diff의 복잡도 검토와 보고 형식. 담지 않는 것: 전체 감사(→ `code-audit.md`)와 정확성 검토. 읽는 시점: 구현 후 또는 단순화 검토 요청 시.

[simplicity.md](simplicity.md)의 선택 순서로 현재 diff를 읽는다.
발견 사항만 보고하며 이 검토 자체는 코드를 수정하지 않는다.
발견 사항을 코드에 반영하는 일은 따로 승인받은 구현 작업에서 한다.

| 태그 | 발견 대상 | 대안 표기 |
|---|---|---|
| `delete:` | 죽은 코드와 쓰지 않는 기능 | 제거 근거. 대체할 것 없음 |
| `stdlib:` | 표준 라이브러리 재구현 | 실제 함수명 |
| `native:` | 플랫폼이 이미 제공하는 동작 | 실제 기능명 |
| `yagni:` | 구현체가 하나뿐인 추상화와 사용하지 않는 설정 | 인라인 또는 현재 필요한 구현 |
| `shrink:` | 같은 동작의 불필요하게 긴 구현 | 짧아진 형태 |

보고는 한 항목당 `파일:줄: 태그 대상. 대안.` 한 줄로 작성한다.
호출자를 추적하기 전에는 죽은 코드로 단정하지 않는다.
대안이 현재 계약을 보존하는지 확인한다.
필수 스모크 테스트나 간단한 자체 검증을 과잉설계로 취급하지 않는다.
정확성과 보안 및 성능 문제는 별도 검토 대상으로 구분한다.
줄 수 감소 예상치를 보고하되 의미와 유지보수성보다 우선하지 않는다.
발견 사항이 없으면 없다고 짧게 보고한다.
