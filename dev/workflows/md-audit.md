# 문서 의미 감사

> 담는 것: 정본 문서와 실제 코드의 의미 차이 조사. 담지 않는 것: 기계 검사(→ `../../kernel/runner.py`)와 문서 작성 규칙(→ `../MD_STANDARD.md`). 읽는 시점: 문서 감사 또는 정비 요청 시.

## 조사

1. `python -X utf8 -m kernel.runner`로 기계 검사 결과를 먼저 확인한다.
2. 현재 실행 환경에서 읽을 수 있는 정본 허브와 관련 문서를 따라간다.
3. 작업 산출물과 보관 문서는 정본 감사 대상에서 제외한다.
4. 문서의 사실 주장을 실제 코드와 대조한다.
5. 관례 위반을 주장하기 전에 형제 구현과 호출자도 확인한다.

넓은 범위는 읽기 전용 검토자에게 그룹별로 위임할 수 있다.
위임 시 파일과 줄의 근거를 요구한다.
읽기 권한이 없는 에이전트 전용 문서는 감사 범위에서 제외하고 그 제한을 보고한다.
게이트가 검사하는 경로와 구조를 수작업으로 반복하는 대신 의미와 판단의 차이에 집중한다.

## 보고

| 판정 | 의미 |
|---|---|
| 정확 | 주장과 구현이 일치 |
| 오래된 설명 | 구현 변경이 문서에 반영되지 않음 |
| 오류 | 설명 자체가 구현 근거와 어긋남 |
| 누락 | 다음 작업을 잘못 이끌 만큼 중요한 계약이 문서에 없음 |

각 발견에는 문서 위치, 문서의 주장, 그 주장에 어긋나는 근거의 파일과 줄을 적는다.
문서 간 중복된 사실과 오래된 판단 근거도 확인한다.
다음 세션이 잘못 행동할 위험이 큰 순서로 정렬한다.
보고서는 `docs/tasks/md_audit_findings_<YYYY-MM>.md`에 쓴다. 다른 세션의 보고서와 파일명이 겹치면 작업 이름을 접미사로 붙인다.
문서 오류는 자동 수정하지 않으며 수정 범위는 사용자가 결정한다.

## 정비 기록

보고서와 정비 메타데이터 외에는 변경하지 않는다.
완료 시 `python -X utf8 -m kernel.maintenance --stamp md-audit`를 실행한다.
이 기록을 남긴다고 해서 커밋해도 된다는 뜻은 아니다.
