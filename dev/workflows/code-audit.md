# 저장소 과잉설계 감사

> 담는 것: 저장소 전체 복잡도 감사와 순위 보고. 담지 않는 것: diff 검토(→ `code-trim.md`)와 부채 수확(→ `code-debt.md`). 읽는 시점: 전체 감사 또는 정비 요청 시.

## 조사

- 전체 저장소의 코드를 조사하고 실제로 확인한 범위를 보고한다.
- [simplicity.md](simplicity.md)의 재사용과 구현 선택 기준을 적용한다.
- 표준 라이브러리나 플랫폼이 제공하는 기능의 재구현을 찾는다.
- 구현체가 하나뿐인 인터페이스와 호출을 그대로 넘기기만 하는 래퍼를 확인한다.
- 쓰이지 않는 설정과 추측성 확장 기능의 호출자를 추적한다.
- 파일이 작거나 호출자가 하나라는 사실만으로 삭제를 결론내리지 않는다.

## 보고

[code-trim.md](code-trim.md)의 태그와 형식을 사용한다.
각 항목에 위치, 과하다고 본 이유, 구체적인 대안을 적는다.
제거 규모와 변경 위험을 함께 고려해 순위를 매긴다.
확정된 죽은 코드와 추가 조사가 필요한 후보를 구분한다.
예상 줄 수와 의존성 감소량을 합산한다.
아무 발견도 없으면 그 사실을 보고한다.

## 경계

감사는 일회성 보고이며 수정이나 코드 삭제를 수행하지 않는다.
정확성과 보안 및 성능 문제는 별도 검토 대상으로 표시한다.
예외로 정비를 마친 시점의 기록만 남길 수 있다.
기록 명령은 `python -X utf8 -m kernel.maintenance --stamp code-audit`다.
이 기록을 남길 수 있다고 해서 자동으로 커밋해도 된다는 뜻은 아니다.
