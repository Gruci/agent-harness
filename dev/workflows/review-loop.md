# 서비스 오너 검수

> 담는 것: 화면과 지표의 업무 의미 검수 및 재검수 절차. 담지 않는 것: 레이블 기준(→ `../../design/UX.md`)과 코드 품질 검토. 읽는 시점: 화면 완성 후 또는 검수 요청 시.

## 검수 요청

| 항목 | 내용 |
|---|---|
| 유형 | 화면 구성, 지표 목록, 문구 또는 복합 |
| 대상 | 원문이나 실제 렌더링 및 상세 설명 |
| 맥락 | 용도와 대상 사용자 |

매일 서비스를 사용하는 사람의 관점으로 검토한다.
화면이 실제 질문에 답하는지와 정보 우선순위를 확인한다.
숫자의 의미와 조건을 사용자가 이해할 수 있는지 확인한다.
일반적인 칭찬 대신 사용자 판단에 영향을 주는 근거를 요구한다.
필요하면 독립적인 검토자에게 위임한다.

## 피드백 처리

| 판정 | 다음 행동 |
|---|---|
| 승인 | 결과 보고 후 종료 |
| 조건부 승인 | 지적된 보완 사항만 수정하고 재검수 |
| 반려 | 누락과 보완 사항을 재작업하고 재검수 |

검토만 요청된 경우 발견 사항을 보고하고 구현을 자동으로 시작하지 않는다.
재작업이 승인된 범위에서는 데이터와 화면의 담당 파일을 구분해 수정한다.
범위가 바뀌면 [feature-workflow.md](feature-workflow.md)의 승인 기준을 적용한다.

## 재검수와 종료

- 이전 판정과 핵심 지적을 함께 전달한다.
- 지적별 반영 내용과 수정된 대상을 제공한다.
- 사용자 판단에 영향을 주는 지적이 없으면 종료한다.
- 같은 내용이 두 번 반려되면 방향을 재논의한다.
- 세 번 반복해도 반려면 편집을 멈추고 근거를 보고한다.

정비 알림으로 실행해 마쳤다면 `python -X utf8 -m kernel.maintenance --stamp review-loop`로 완료 시점을 기록한다.
이 기록은 검수 결과와 별개이며, 기록을 남긴다고 해서 커밋해도 된다는 뜻은 아니다.
