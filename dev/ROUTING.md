# dev/ROUTING.md — 모델 라우팅과 위임, 모듈 소유권

> 담는 것: 일을 누구에게 맡길지(모델·에이전트·effort)와 동시 편집을 막는 소유권 단위. 담지 않는 것: 세션 행동 규칙 전체(→ `../CLAUDE.md`)·에이전트별 계약(→ `../.claude/agents/`)·하네스 실물 지도(→ `HARNESS.md`). 읽는 시점: 에이전트에 위임하기 전, 병렬 구현을 나눌 때.

## 모델 라우팅 — 토큰 볼륨 × 판단 스테이크

메인 루프는 **Opus**다. 모델은 버전 없이 계열 이름으로 적는다 — 에이전트 모델의 정본은 frontmatter 별칭이고 검사 29 가 정책표와 대조한다. 컨텍스트가 1M이라 정본 MD와 소스는 직접 Read하는 것이 기본이다. 위임은 비용을 아끼는 수단이 아니라 **서로 독립적인 대규모 작업을 병렬로 돌리는 수단**이다.

| 역할 | 모델 | 언제 |
|------|------|------|
| 메인 루프 — 계획·구현·리서치·검수 | Opus | 상시 |
| plan 통째 실행 — 3단계 구현 | Fable 에이전트 (executor) | 승인된 plan이 파일 8개 이상이거나 레이어 3개 이상 횡단 |
| 대규모 병렬 구현 지휘 | Fable 에이전트 (orchestrator) | 승인된 plan에 서로 겹치지 않는 트랙이 3개 이상. 파일 소유권 배정과 공유 파일 순차 적용의 정본은 에이전트 파일 |
| 비중이 큰 단발 판단 | Opus 메인 루프 + effort 상향 | plan 최종 검토·스키마 설계·디자인 채택 |
| 대량 기계적 정독·팬아웃 | Sonnet 에이전트 | 수십 파일 독립 스캔 |

- **에이전트 생성 최소화** — 몇 번의 툴 호출로 끝날 일은 위임하지 않는다. 에이전트를 띄우는 비용이 더 크다. 오케스트레이션은 겹치는 부분을 공유 파일로 뺀 뒤에도 서로 겹치지 않는 트랙이 3개 이상일 때만 쓴다. **크지만 순서대로 해야 하는 과업에는 쓰지 않는다.**
- **오케스트레이션 중에도 git·검증·보드는 메인 세션이 전담한다. 워커 보고는 증거가 아니다.**
- **단발 위임의 입력은 결정에 필요한 요약과 파일 경로다.** 원본을 대량으로 주입하지 않는다.
- **조정은 effort로 한다** — 비용을 줄일 때는 모델을 낮추지 말고 effort를 낮춘다. 판단력을 높일 때도 모델을 바꾸지 말고 effort를 올린다. 장황함은 프롬프트로 제어한다. 되돌리기 비싼 결정에 검증 전용 에이전트를 붙이지 않는다 — Opus는 시키지 않아도 자기 작업을 검증하므로 중복 검증은 토큰만 쓰고 결과를 바꾸지 않는다. effort의 정본은 각 에이전트 frontmatter다.
- **Fable 위임은 절차가 아니라 목표로 준다.** 단계를 나열한 브리프는 장기 자율 실행의 품질을 떨어뜨린다. 게이트와 완료 조건은 제약이라 남기고 순서 지시만 뺀다. 브리프만 읽고도 일을 할 수 있는지는 plan의 No Placeholders 규칙이 보장한다.
- 에이전트는 요약과 `detail_path`를 나눠서 반환한다. 상세는 파일로 남기고 반환문에는 결론과 file:line 포인터만 넣는다. 반환문이 너무 길면 SubagentStop 훅이 막는다.
- **세션 분리** — 태스크가 완결되면 `/clear`한다. 프로젝트급 작업 여러 개를 한 세션에 끌고 가지 않는다.

## 모듈 소유권

| 종류 | 고유 사항 |
|------|----------|
| **동시 편집 금지** | 컴포넌트 그래프 정본과 그 승인 기록, 프로파일. 병렬 체제에서는 `workboard/` 의 「손대는 곳」이 잠금 단위다 |
| **컴포넌트 경계** | 제품 코드는 승인된 컴포넌트 하나에 속하고, 허용 의존은 그래프 간선이 정한다. 관측된 의존은 자동으로 허용되지 않는다 |
| **역할 배치** | 정책·유스케이스·포트·조회·어댑터·전달의 책임은 `ARCHITECTURE.md` 가 정한다. 그래프 밖 배치는 `component_classification` 이 `[DECISION]` 으로 잡는다 |
| **환경변수** | 전부 프로파일이 선언한 설정 모듈을 거쳐 읽는다. 다른 모듈이 직접 읽으면 게이트가 막는다 |

의존 방향의 정본은 컴포넌트 그래프(계약은 `COMPONENTS.md`)이고, 코드 관례는 `DEVGUIDE.md`다.

## 하네스 등록

에이전트와 스킬은 세션에 자동 주입된다. 정본은 각 디렉토리 파일이고 **사람용 전체 지도는 `HARNESS.md`**다. 하네스 구성이 바뀌면 같은 턴에 지도를 갱신하고, 하네스 지도 검사(검사 28)가 지도를 실물과 대조한다. 모델과 effort는 각 에이전트 frontmatter가 정본이고, 에이전트 모델 정책 검사(검사 29)가 이를 프로파일의 정책표와 대조한다 — 한쪽만 바꾸면 막힌다.
