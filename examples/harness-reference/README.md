# 첫 코드 전 분류 예시

> 담는 것: 정책과 유스케이스 및 선언 포트를 함께 검증하는 실행 예시. 담지 않는 것: 앱 언어 선택 기준(→ ../../dev/workflows/harness-assembly.md). 읽는 시점: 선택한 스택에 분류와 검사를 연결할 때.

Python은 이 예시를 실행하는 언어이며 새 프로젝트의 기본 언어가 아니다.
실제 프로젝트는 사용자가 선택한 스택에 맞게 분류 위치와 검사기를 연결한다.
예시 그래프를 복사했다고 해서 사용자가 구조를 승인한 것으로 보지 않는다.
분류의 정본은 [컴포넌트 그래프](docs/architecture/components.json)다.
현재 구조와 소스 분류는 [생성 기능 지도](docs/architecture/feature-map.md)에서 확인한다.

업무 규칙은 세 개 이상 주문할 때 전체 금액의 10%를 할인하는 것이다.
금액은 정수 센트로 계산하며 소수점 이하는 버린다.
상품 가격 조회를 포트로 선언해서, 메모리 저장 방식이 가격 정책 코드로 번지지 않게 한다.
테스트는 같은 조회 계약을 실제 메모리 어댑터와 페이크에 적용한다.
유스케이스 테스트는 페이크에 상품 조회가 실제 전달됐는지도 확인한다.

이 디렉터리에서 `python -m unittest discover -s tests`로 행동 계약을 검증한다.
저장소 루트에서 `python -m kernel.feature_map --root examples/harness-reference`로 지도를 생성한다.
같은 명령에 `--check`를 붙이면 파일을 변경하지 않고 지도 차이만 검사한다.
지도와 테스트의 성공은 사용자 승인 증거를 대신하지 않는다.
