# docs/BACKLOG.md — 잔여 백로그

> 담는 것: 아직 시작하지 않은 일과 그 판단 근거. 담지 않는 것: 지금 누가 어떤 작업을 맡고 있는지와 시작부터 완료까지의 절차(→ `workboard/README.md`)·세션 행동 규칙(→ `CLAUDE.md`). 읽는 시점: 다음 과업을 고를 때.

> **진행 중인 과업은 여기 없다.** `workboard/` 에 있다. 거기서는 파일 하나가 과업 하나이고
> git 으로 추적하지 않는다. 이 파일에는 **남은 일**만 적는다.

> **열린 것만 남긴다.** 완료했거나 기각한 행은 지운다. 경위는 git 이력과 `docs/tasks/archive/`에 남아 있고, 여기에 쌓이면 지금 무엇이 남았는지 읽어낼 수 없다.
> ⚠️ **손대기 전에 적힌 내용을 지금 코드와 대조한다.** 원류 프로젝트에서 백로그를 정리할 때 8건 중 5건은 "막상 시작해 보니 이미 해결돼 있었다"였고, 3건은 전제 자체가 낡아 있었다. 백로그는 **직접 확인한 사실이 아니라 기억**이다.

> 📦 **이 파일은 새 프로젝트로 함께 복사된다.** `PROJECT.md` 처럼 **새 프로젝트가 채우는 문서**다. 하네스를 clone 해 가면 이 파일도 함께 가서 그 프로젝트의 남은 작업을 담는다. 그래서 배포본은 비어 있는 것이 정상이다. 하네스를 만들며 생긴 메모를 여기 남기면 **그 메모가 모든 새 프로젝트에 그대로 딸려 간다.** 하네스 자신의 설계 판단은 `dev/REJECTED.md` 에 적는다.
