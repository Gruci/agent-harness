# design/COMPONENTS.md — 컴포넌트 패턴

> 담는 것: 재사용 컴포넌트의 용도 경계와 쓰면 안 되는 경우. 담지 않는 것: props와 시그니처(정본은 코드)·배치와 간격(→ `design/LAYOUT.md`). 읽는 시점: 새 컴포넌트를 만들기 전. 이미 있는 패턴을 모방하는 것이 기본이다.

아직 컴포넌트가 없다. **새 컴포넌트 패턴을 만든 그 턴 안에 여기 기록한다.** 나중에 몰아서 기록하지 않는다.

## 기록 형식

패턴마다 이름, 정본 파일 경로, 언제 쓰는가, 구조 요점(마크업 스켈레톤 또는 props)을 적는다.

## 타이포그래피 원칙 (impeccable 기반)

- **본문 라인 길이 상한**: 65~75ch (`max-width: 65ch`).
- **폰트 페어링**: 비슷한 산세리프 두 개를 짝짓지 않는다. 대비가 분명한 조합(serif + sans, geometric + humanist)으로 짝짓거나, 한 패밀리를 여러 웨이트로 쓴다.
- **히어로/디스플레이 제목 상한**: `clamp()` max ≤ 6rem. 그보다 크면 제목이 화면을 압도한다.
- **디스플레이 자간 하한**: ≥ -0.04em. 더 좁히면 글자끼리 붙는다.
- **텍스트 래핑**: h1~h3에 `text-wrap: balance`, 긴 산문에 `text-wrap: pretty`.

## 절대 금지 패턴 (impeccable Absolute Bans)

| 패턴 | 왜 금지 | 대안 |
|------|--------|------|
| Side-stripe border (1px 초과 좌/우 컬러 보더) | 의도적이지 않은 장식 | 풀 보더, 배경 틴트, 아이콘, 또는 없음 |
| Gradient text (`background-clip: text`) | 장식용, 의미 없음 | 단색. 강조는 웨이트·사이즈로 |
| Glassmorphism as default | 장식 블러 남발 | 희소하고 의도적일 때만, 또는 없음 |
| Hero-metric 템플릿 (큰 숫자 + 작은 라벨 + 그라디언트) | SaaS 클리셰 | 맥락 있는 데이터 표현 |
| 동일 카드 그리드 반복 (아이콘+제목+텍스트 ×N) | AI 생성물 전형 | 콘텐츠에 맞는 다양한 어포던스 |
| 모든 섹션에 작은 대문자 아이브로우 | 2023년 무렵 AI 생성물의 상투 문법 | 하나의 의도적 브랜드 시스템이거나 없음 |
| 번호 섹션 마커 (01/02/03) 디폴트 | 아이브로우의 변형 | 실제 순서가 정보일 때만 사용 |
| 컨테이너 밖 텍스트 오버플로 | 모바일/태블릿 깨짐 | 모든 브레이크포인트에서 테스트 |

## 모션 원칙 (impeccable 기반)

- 모션은 처음부터 함께 만든다. 다 만든 뒤에 덧붙이지 않는다.
- CSS layout 속성 애니메이션은 진짜 필요할 때만.
- **ease-out 지수 커브** (quart/quint/expo). bounce/elastic 금지.
- 고급 모션은 라이브러리 활용 (motion, gsap, anime.js, lenis 등).
- **`@media (prefers-reduced-motion: reduce)` 필수** — 모든 애니메이션에 대안(crossfade 또는 즉시 전환)을 둔다.
- reveal 애니메이션은 이미 보이는 기본 상태를 강조하는 용도다. 콘텐츠가 보일지 말지를 클래스 트리거에 걸면 안 된다. 숨겨진 탭에서는 reveal이 실행되지 않아 빈 화면이 된다.

## 규칙 (확정분)

- 한 페이지 전용 컴포넌트와 두 페이지 이상이 쓰는 공용 컴포넌트는 디렉토리로 가른다. 디렉토리 이름은 고른 스택의 관례(`dev/CONVENTIONS.md` 「스택 관례」)가 정한다
- 공용으로 옮기는 시점은 두 번째 사용처가 실제로 생겼을 때다. 미리 일반화하지 않는다
- 툴팁·카드·탭 등 반복 UI는 첫 구현을 정본으로 등재하고, 이후 구현은 그것을 따라 만든다
