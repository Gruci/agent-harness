# design/COLORS.md — 색상 시스템

> 담는 것: 각 색이 무슨 의미이고 어디에 쓰는지. 담지 않는 것: 색상 값 자체(정본은 프로파일 `CHECK_PATHS["ui_tokens"]` 가 가리키는 토큰 파일과 CSS 변수)·차트 계열색(→ `design/CHARTS.md`). 읽는 시점: 새 색을 쓰거나 기존 색의 의미가 헷갈릴 때.

아직 디자인 토큰이 없다. 첫 UI 작업 시 이 문서를 채운다.
> **규칙: 색상 정본은 토큰 파일(`CHECK_PATHS["ui_tokens"]`) + CSS `:root` 변수 — 이 MD는 의미·사용처만 서술 (값 손사본 금지, drift 원인).**

## 정해야 할 것 (첫 UI 작업 시 사용자와 확정)

- [ ] 브랜드 기본색 / 강조색
- [ ] 증감 색 의미론 (예: 상승=빨강/하락=파랑 — 국내 금융 관례 vs 반대)
- [ ] 상태색 (성공/경고/에러)
- [ ] 텍스트 위계 (`--text-main` / `--text-sub` 등)
- [ ] 다크모드 여부
- [ ] 색상 전략 (아래 4단계 중 택 1)

## 색상 전략 (impeccable 원칙 — 첫 UI 전 결정)

색을 고르기 전에 **전략**을 먼저 정한다:

| 전략 | 브랜드 색 비중 | 적합 케이스 |
|------|---------------|------------|
| Restrained | 틴트 뉴트럴 + 강조색 ≤10% | 프로덕트 기본, 미니멀 |
| Committed | 채도 색 30~60% | 아이덴티티 중심 페이지 |
| Full palette | 3~4 역할색, 각각 의도적 사용 | 캠페인, 데이터 시각화 |
| Drenched | 표면 자체가 색 | 히어로, 캠페인 |

## 색상 원칙 (impeccable 기반)

- **OKLCH 사용** — 새 프로젝트에서 색 정의 시 OKLCH 우선.
- **대비 검증 필수**: 본문 텍스트 ≥ 4.5:1, 대형 텍스트(≥18px 또는 bold ≥14px) ≥ 3:1. placeholder도 동일.
- **회색 텍스트 + 컬러 배경 = 빠짐 현상** → 배경 색조의 어두운 셰이드 사용 또는 텍스트색 투명도.
- **틴트 뉴트럴**: 브랜드 색조 방향으로 chroma 0.005~0.015 추가. "따뜻해 보이니까 웜" 식의 디폴트 틴팅 금지.
- **크림/샌드/베이지 배경 금지** — OKLCH L 0.84-0.97, C < 0.06, hue 40-100 영역은 AI 생성물의 포화 디폴트. 대안: (a) 채도 있는 브랜드 색 배경, (b) chroma 0 순수 오프화이트, (c) 분명한 미드톤 틴트 뉴트럴.
- **다크/라이트 결정은 디폴트가 아님** — "누가, 어디서, 어떤 조명 아래, 어떤 무드로 쓰는가" 한 문장 시나리오를 먼저 쓰고 그에서 답이 나와야 함.

## 규칙 (확정분)

- hex 하드코딩 금지 — 토큰 파일 상수 또는 CSS var (게이트)
- 투명도는 `hexAlpha()` 헬퍼(첫 구현 시 토큰 파일 옆에 생성) — 문자열 접합(`+'99'`) 금지
- 두 페이지 이상 쓰는 색은 반드시 중앙 상수로 승격
