# design/UX.md — UX 원칙·레이블 규칙

> 담는 것: 사용자에게 보이는 문구와 정보 위계의 판단 기준, 금칙 조어. 담지 않는 것: 코드 식별자 이름(→ `dev/NAMING.md`)·시각적 배치(→ `design/LAYOUT.md`). 읽는 시점: 사용자 노출 텍스트를 쓰거나 화면 정보 우선순위를 정할 때.

어느 프로젝트에나 통하는 보편 원칙과 impeccable 디자인 품질 기준을 담는다. 프로젝트 고유 UX 규칙은 확정되는 대로 추가한다.

## 레이블 원칙

- **자기설명 레이블**: 처음 보는 사용자가 설명 없이 이해할 수 있어야 한다.
- **조어 금지**: 마케팅성 신조어와 내부 용어를 사용자에게 보이는 텍스트에 쓰지 않는다. 리뷰에서 조어를 찾으면 그 문자열을 `harness_profile.py`의 `VOCAB["ui_denylist"]`에 추가한다. 그러면 다음부터 UI 라벨 금칙어 검사(검사 6)가 막는다. 커널 파일은 `--upgrade` 때 덮어써지므로 거기에는 적지 않는다.
- 값이 없으면 `'-'`, 로딩 중이면 `'불러오는 중…'`으로 통일한다.
- 이모지는 쓰지 않는다. 문서로 정한 예외만 허용한다.

## 정보 위계 원칙

- **결론 → 근거 → 상세** 순서: 화면 맨 위에 결론(요약)을 두고, 그 아래로 근거와 상세를 둔다.
- 핵심 지표가 스크롤 아래에 묻히지 않게 배치한다.
- 지표 옆에는 맥락(비교 기준·기간·출처)을 함께 적는다. 숫자만 따로 보여주지 않는다 (Footnote).

## 필터·인터랙션 원칙

- 비슷한 화면끼리는 필터 UI와 동작을 맞춘다. 한쪽만 바꾸지 않는다.
- (프로젝트 고유 규칙 확정 시 추가)

## AI 슬롭 테스트 (impeccable 기반)

누군가 이 인터페이스를 보고 "AI가 만들었네"라고 확신할 수 있으면 실패다.

**카테고리-반사 체크 (2단계):**
1. **1차**: 카테고리만 보고 테마와 팔레트를 맞힐 수 있으면, 훈련 데이터에서 가장 먼저 떠오르는 답을 그대로 쓴 것이다. 다시 만든다.
2. **2차**: 카테고리와 "안티레퍼런스"(피하려고 정한 참고 사례)로 미학 계열을 맞힐 수 있으면, 첫 번째 함정을 피하려다 한 단계 아래 함정에 빠진 것이다. 다시 만든다.

## 디자인 품질 기준

- **프로토타입이 아닌 프로덕션 수준** — 완성된 코드, 반응형, 접근성, 버그 없음.
- **세부사항까지 챙긴다** — 모든 컴포넌트와 페이지를 여러 뷰포트와 상태에서 검증한다.
- `/impeccable critique` — UX 휴리스틱 점수 리뷰
- `/impeccable audit` — 기술 품질(a11y, 성능, 반응형) 점검
- `/impeccable polish` — 출하 전 최종 품질 패스
