# workboard/ — 과업 보드와 worktree 프로토콜

> 담는 것: 지금 누가 무엇을 잡고 있나(이 디렉토리의 파일들)와 착수~완료 절차. 담지 않는 것: 남은 일(→ `docs/BACKLOG.md`)·세션 행동 규칙(→ `CLAUDE.md`)·훅의 차단·경고 구분(→ `dev/HARNESS.md`). 읽는 시점: 과업 착수 전.

## 자리가 레포 루트인 이유 — 에이전트 중립

보드와 worktree 는 **어느 에이전트의 것도 아니다.** `.claude/` 밑에 두면 Codex 가 남의 전용
폴더를 드나들어야 하고, 에이전트마다 자기 폴더에 두면 보드가 갈라진다 — 같은 기능이면 같은
보드를 본다. 과업을 에이전트별로 나누지 않으며, 담당 도구를 밝힐 일이 있으면 과업 파일 안에
`- 담당: claude` 처럼 적는 것으로 충분하다. 겹침 판정도 한 벌이다 — `kernel/workboard.py` 를
Claude 훅과 Codex 진입점(`kernel/hook.py`)이 같이 쓴다.

## 보드는 공유 체크아웃 한 곳이다

**과업 파일은 공유 체크아웃(메인 체크아웃 루트)의 `workboard/` 에만 둔다.** worktree 안에도
같은 경로가 있지만(이 README 는 git 추적이라 따라온다) 거기 쓰면 아무도 못 본다 — 보드가
세션 수만큼 갈라져 공유 채널이 성립하지 않는다.

훅은 `git rev-parse --git-common-dir` 로 공유 루트를 찾아 항상 한 곳을 본다
(`kernel.workboard.board_dir()`). 사람이 볼 때도 공유 체크아웃 경로에서 `ls` 한다.

## 이 디렉토리는 git 에 없다

`README.md` 하나만 추적하고 **과업 파일은 `.gitignore`** 다. 세션이 전부 같은 머신에서 도니
파일시스템이 곧 공유 채널이고, git 을 한 번 더 거치면 두 가지가 생긴다 — 모든 세션이 한 파일
같은 자리를 고쳐 **충돌**하고, 보드를 남에게 보이려고 **머지가 필요**해진다. 원류 MIS 의
2026-09 실측으로 그 비용이 보드 전용 PR 51건(전체 PR 의 25%)과 충돌 해소 34건이었다.

대가는 이력이 안 남는 것이다. 보드는 "지금"을 담는 물건이고 끝난 과업은 git log 와
`docs/tasks/archive/` 에 남으므로 감수한다. 같은 머신 전제이기도 하다 — **다른 머신이나
클라우드 세션이 섞이면 이 전제가 깨진다.**

## 파일 하나가 과업 하나

파일명은 **수정 범위**다. 랜덤 식별자를 쓰지 않는다 — `ls` 를 했을 때 겹침이 보여야 하고,
같은 범위를 둘이 잡으면 파일명이 같아져 착수 시점에 선다.

이름은 `<영역>-<대상>` 두 토막이고, 영역은 화면·API 의 첫 세그먼트나 하네스 영역
(`gates`·`hooks`·`docs`·`ci`)이다. 단위는 **파일 경로가 아니라 화면·기능**이다 — 한쪽이
컴포넌트만, 다른 쪽이 CSS 만 건드려도 앞쪽이 클래스명을 바꾸면 뒤쪽 작업이 화면에서 무효가
된다. 경로를 납작하게 편 이름(`frontend-src-components-…`)은 쓰지 않는다.
**같은 범위에 다른 이름을 지으면 이 장치가 무력해진다** — 새 이름을 짓기 전에 `ls` 로 본다.

### 서식

```markdown
- 범위: admin-report-viewers
- 과업: feat/report-viewers-sector-tabs #sid:0e6cda52
- 항목:
  - [x] 부문 탭으로 전환
  - [ ] 제목 폰트 키우기      (2026-09-16 추가 요청)
- 손대는 곳:
  - frontend/src/components/admin/salesStatus/*
  - web/static/admin/admin.css
- 시작: 2026-09-16
- 상태: 진행
```

- `#sid` 는 실행 환경의 session_id 앞 8자다. 식별자가 제공되지 않으면 작업용 ID 를 한 번
  생성해 쓰되 런타임 ID 로 검증됐다고 주장하지 않는다. **훅의 "내 과업인가" 판정이 파일명이
  아니라 이 태그로 돈다** — 범위 이름을 바꿔도 자기 과업을 남의 것으로 오인하지 않는다.
- `손대는 곳` 은 글로브이고 `check_workboard_overlap.py` 가 편집 시점에 남의 과업과
  대조한다. 넓게 적어도 된다 — 경고이지 차단이 아니다.
- `상태` 는 `진행` 으로 시작해 PR 이 나가면 `PR#n` 으로 바꾼다. 그 값이 겹칠 때의 순서를 정한다.
- 자기 파일만 갱신하며 다른 세션의 파일과 미커밋 변경을 보존한다. 위임 워커는 부모의 과업
  파일을 공유하며 배정된 파일만 수정한다.

## 착수 — 같은 범위가 이미 있으면 묶는다

과업이 늘어나는 실제 상황은 한 화면에 변경이 여러 개 필요할 때다. 흩지 말고 묶는다.

| workboard 에 그 범위가 | 하는 일 |
|---|---|
| 없다 | 새 파일 만들고 착수 |
| 있고 `상태: 진행`(PR 전) | 그 파일 `항목` 에 줄 추가 → **그 세션이 같이 처리** (합류) |
| 있고 `상태: PR#n` | 그 브랜치를 base 로 worktree 를 딴다 (쌓기) |

합류가 기본이다. 쌓기는 앞 과업이 이미 PR 로 나가 손댈 수 없을 때만이고, 이유는 속도가
아니라 **정확성**이다 — 뒤 세션이 앞 결과를 보면서 작업하므로 이름 어긋남이 구조적으로 안
생긴다. ⚠️ **쌓기는 순서가 계약이다** — 뒤를 먼저 머지하면 앞 커밋이 조상으로 딸려 들어간다.

```bash
# 쌓기: 기본 브랜치가 아니라 앞 과업 브랜치에서 딴다
git worktree add worktrees/<범위>--<sid8> -b <브랜치> <앞-브랜치>
```

## 작업 격리

작업 전 `git worktree list` 와 현재 브랜치를 확인한다.
추가 worktree 가 없고 단일 세션이면 메인 체크아웃에서 작업할 수 있다.
추가 worktree 가 있으면 공유 메인 체크아웃은 조회용이며 구현은 자기 worktree 에서 한다.

- worktree 자리는 **공유 체크아웃 루트 기준 상대경로 `worktrees/<이름>` 하나로 고정**이고,
  **이름은 workboard 범위 이름 + `--<sid8>`** 이다. 절대경로·외부 디스크·다른 worktree 안은
  받지 않는다 — 명령은 공유 루트에서 상대경로로 실행한다. `ls workboard/` 와
  `git worktree list` 가 눈으로 바로 조인되고, `kernel/worktree.py` 가 Claude·Codex 양쪽에서
  생성 시점에 이름·자리를 강제한다(범위 일치는 내 보드 파일이 있을 때만).
- 생성과 진입은 두 단계다 — 정본 목록은 폴더가 아니라 `git worktree list` 다:

  ```bash
  git worktree add worktrees/<범위>--<sid8> -b <브랜치> origin/<기본브랜치>
  # Claude 세션은 이어서 EnterWorktree(path="worktrees/<범위>--<sid8>") 로 진입한다
  ```

  `EnterWorktree(name)` 생성은 쓰지 않는다 — 그 툴은 생성 위치가 `.claude/worktrees/` 로
  고정이라 루트 규약과 어긋나고, 훅이 차단하며 위 두 명령을 제시한다. path 진입은 위치
  무관이라 그대로 쓴다.
- 생성 기준 브랜치는 원격 기본 브랜치의 실물을 확인해 고른다. 브랜치 이름은 작업 성격에
  맞는 접두(`feat/`·`fix/`·`perf/`·`chore/`·`docs/`)를 쓴다.
- 구현과 검증은 같은 worktree 에서 수행한다.
- 의존성 디렉터리를 다른 worktree 에 junction 이나 symlink 로 연결하지 않는다. 필요한
  의존성은 해당 트리에 설치한다.
- 내장 worktree 디렉터리는 로컬 git 제외 설정에 등록해 검색·검사 대상에 섞이지 않게 한다.
- 같은 기능을 위임한 워커는 부모 worktree 를 공유하며 편집 소유권으로 충돌을 방지한다.
  별도 PR 을 만드는 독립 트랙만 별도 worktree 로 격리한다.
- 실행 중인 워커의 worktree 는 제거하지 않는다. 자동 정리되는 실행 환경에서 독립 트랙을
  쓰면 작업 전에 미추적 표식과 `git worktree lock` 으로 보호한다.
- 각 worktree 에서 검사는 그 체크아웃의 커널을 사용한다.

## 완료

1. 승인된 범위의 구현과 검증을 완료한다.
2. 두 작업 문서를 공통 개발 절차에 따라 `docs/tasks/archive/` 로 보관한다.
3. 커밋과 원격 반영은 사용자 승인 범위와 실행 환경 지침에 맞춰 수행한다. 원격에 PR·CI 가
   있으면 push → PR → **CI 통과 확인** → merge 순이고, CI 판정 명령은 단독 실행한다
   (파이프·체인을 붙이면 판정 exit code 가 사라져 훅이 막는다).
4. 머지한 자기 worktree 만 제거하고 그다음 자기 브랜치를 정리한다.
5. **자기 과업 파일 삭제는 맨 끝이다.** 머지 직후 같은 턴에 한다 — Stop 훅
   `check_worktree_residue.py`·`check_editing_lock.py` 가 잔존 시 종료를 경고한다.

과업 파일이 있다는 이유만으로 진행 중인 세션을 종료 불능으로 만들지 않는다.
머지 여부를 추론한 잔존 판정은 경고이며 확인 없이 파일을 삭제하지 않는다.

## 겹친 채로 갈 때

workboard 는 겹침을 알려줄 뿐 해소하지 않는다. 이미 둘 다 편집 중이면:

1. **먼저 PR 을 낸 쪽이 우선이다.** `상태: PR#n` 이 순서를 고정한다.
2. 나중 쪽은 앞이 머지된 뒤 자기 브랜치에 기본 브랜치를 merge 해서 해소한다.
3. **해소 직후 전체 검증을 다시 돌린다** — 충돌 해소는 코드를 바꾸는 행위다.
